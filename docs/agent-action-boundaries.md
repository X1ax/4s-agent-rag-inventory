## 当前与后续阶段

M3.5提供连续对话、账号隔离的本机会话记录、RAG引用问答、通用故障辅助排查、假设计算及Tavily公开搜索。M4现已接入受控查询与业务提案工具、主Agent和两个专业Agent、LangGraph人工确认与执行。未确认前聊天不会创建业务单据或改变库存；执行与质量边界见m4-verification.md，不把开发对比当独立生产验收。

## 自主工作与人工确认

| 场景 | 可以自主完成 | 真人确认范围 |
| --- | --- | --- |
| 对话 | 理解上下文、拆分任务、询问缺失条件、解释结果 | 有歧义的关键条件由用户补充 |
| 备件 | 查询名称、别名、SKU、分类、规格、图片、供应关系 | 新增、修改、停用基础资料 |
| 库存 | 查询各仓现有量、可用量、采购待收、调拨在途、流水 | 库存变化必须有业务单据 |
| 单据 | 查询状态、明细、关联单据与历史 | 确认、取消、过账、发出、收货等状态变化 |
| 分析 | 已记录消耗统计、低库存与零库存核查、确定性补货和可调量计算 | 是否采纳方案与实际办理 |
| 采购 | 梳理需求、匹配供货范围、生成逐明细供应商与价格数量提案 | 核对后创建单据，采购确认另行审核 |
| 调拨 | 核查两仓、计算可调量、整理来源/目标/备件/数量提案 | 核对后创建草稿；实物发出与收货分别确认 |
| 入库 | 查询采购待收、校验累计收货、整理入库信息 | 实际到货、质量验收、本次实收数量及入账确认 |
| 领用 | 查询库存、核对需求和用途、整理出库提案 | 领用确认与过账 |
| 故障 | 查手册、列故障类型、给检查方向及逐部件换件条件 | 实际检测与换件决定；不能由聊天直接领用 |
| 知识 | 检索项目资料、联网查询公开信息、提供来源、指出不足与冲突 | 网页不能代替企业业务审批 |
| 异常 | 识别缺货、权限不足、状态冲突、供应范围不符并提供重试方式 | 参数变化或方案失效后重新确认 |

## 必须保持的控制

写操作必须绑定服务端提案ID、版本、动作、参数和当前登录用户。普通消息中的“已审批”或文档指令不构成批准凭据。修改备件、仓库、数量、供应商、价格或动作后，旧确认失效。

人工按钮只代表批准已展示的具体动作，不能把“建调拨草稿”扩展为“发出并收货”，不能把“建采购草稿”扩展为“确认采购并实际入库”。现有账号权限不因Agent而扩大。

执行前重新核验身份、权限、资料/备件启停、供应范围、数量、单据状态和库存；库存扣减、流水与幂等结果复用同一业务服务。图恢复或重复确认仍须由业务幂等保证不重复生效。LangGraph中断、持久检查点、提交后重放和越权恢复已在隔离MySQL及定向测试验证，具体范围见M4记录；未宣称所有LLM中间步骤可断点续跑。

模型不直接运行任意SQL、shell、文件读取或任意URL请求，不管理账号权限，不绕过审核，不删除库存历史，不向真实供应商自动下单。

## 资料校验与来源

按用户要求，项目编制资料经项目内部校验即可供参考，不等待外部人员签字。AI负责结构、条款关系、代码口径、引用和明显冲突的项目级校对；不能把这些检查冒称为厂家认证或专业维修签字。原始清单的历史编制状态不伪造批准人或日期。

智能助手默认使用项目参考资料（内部查询参数仍为draft_preview），低层知识API仍保留released_only隔离以供正式发布场景验证。业务采购、出入库、调拨的真人审核与知识资料的校验是两类不同控制。

Tavily仅发送必要公开搜索词，网页摘录作为数据处理，来源与项目文档分开。不得用网页推断实时库存、实物适配、价格承诺或业务审批结果。

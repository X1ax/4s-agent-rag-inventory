## 2. 修复内容

### 2.1 Chroma 尾批持久化

锁定版本 Chroma 1.5.9 在旧 HNSW 配置 `batch_size=16 / sync_threshold=16` 下，最后不足阈值的一批向量未形成完整磁盘 ID 映射。实际复现了计数正常、普通探针成功，但重开后带文档过滤查询报 `Error finding id` 的情况。仅关闭客户端不能作为尾批落盘保证。

`backend/app/retrieval.py` 保留批量 16，将落盘阈值设为 1。生产实现继续使用公开 API，没有读写内部 pickle、吞掉错误、取消资格过滤或加入隐式重试。确定性回归测试仅检查自己生成的测试索引内部快照，先复现失败再验证修复。57 项检索测试通过；额外运行 40 代构建、120 次重开、720 次过滤检索及 240 次故障域资格阻断检查，均符合预期。

依据包括锁定版本的 [local_hnsw.rs](https://raw.githubusercontent.com/chroma-core/chroma/1.5.9/rust/segment/src/local_hnsw.rs) 及本地复现。有限重复验证不能保证免疫所有平台或其他原因的索引故障；`index_query_failed` 仍显式返回。

已备份旧 active 指针，停止经 PID、命令行及端口核实的本项目后端，使用真实 `BAAI/bge-m3` 重建当前资料并重启。当前运行索引为 `01efb5f874eb427f9ed812cb842df97a`：19 份资料、242 单元、86 上下文；构建 16 次 Embedding 请求、40339 token、0 重试。没有将草稿改成正式生效制度。

### 2.2 回答与工具边界

- 日期区间、补货示例必须进入已有服务端确定性计算分支；假设摘录保留用户的假设标记，不能只列规则或重复追问已给条件。
- `outside_scope/refused` 清除业务结论和换件卡片时，仍在限制中保留范围及安全分流理由。
- 制度结论按实际引用拆分，批准版本、金额及授权要求引用采购规程完整上下文，避免借相邻条款补出未被当前引用支持的条件。
- 实时故障库存分支统一说明：文档不能证明实时库存、目录适配或单车需求数量；HTTP 与评测共用 `live_data_answer`。
- 具体调拨建议必须引用对应 `calculated` 结果。正文及追问不能携带无引用的具体调拨量，也不能用另一个 SKU 的有效计算豁免该限制。8 种正文/追问与其他 SKU 组合已回归。

### 2.3 评测器可信度

`evals/run_acceptance.py` 修复早期 Embedding/查询失败后缩小分母的问题：库存目标题固定 35、预期证据组固定 71；故障目标组固定 19。失败仍计入分母，库存证据同时核对条款与版本。回答默认按实际路径使用库存 hybrid、故障 dense，可显式指定模式，历史 dense 成绩保留。

`evals/compare_agents.py` 使用有真实期初成本、独立供货报价和门店售价、角色分离审核的唯一前缀夹具。核对实际工具对象、日期、数量、报价版本、确认前数据库变化、确认后真实单据及重复确认后的完整业务快照。模型异常时也保存已发生的业务变化和不完整用量标记。

创建单据接口实际返回 `id/status/replayed`，不返回 `kind`。原计分器误要求响应包含 `kind`，会把成功采购、调拨判失败；现根据数据库核对单据种类及明细，响应仅检查真实契约。正例验证真实单据通过，假重复 ID、错误种类或没有新增草稿仍不能通过。评测器 18 项定向测试通过。

# M3.4 生命周期与组合检索验收

日期：2026-10-23。完成受控检索内核、索引恢复命令与开发集配对比较；没有新增知识问答API、页面、对话模型调用、Agent或MySQL表，未提交Git。

## 实现与边界

`knowledge_lifecycle.py`复用受控解析器，每次查询按知识域重新解析并校验当前来源。与索引快照逐文档比较身份、版本、原生哈希、路径及发布元数据；修改、删除、撤回、被替代、状态未知、版本尚未索引的来源都不进入候选，未变化来源继续服务。默认现行范围仍为空，显式草稿预览才能查询现有19份待核准资料。发布记录与生效时间每次复核；索引完成不代表正式发布。

故障来源登记或部件类型映射改变时暂停故障域；公共规则缺失、失效或未获本次查询资格时同样暂停该域，其他知识域可以继续查询。清单结构不可验证时关闭对应知识域，不猜测来源。每次返回前再次校验来源快照，途中变化抛出`knowledge_changed`并丢弃结果。未来M3.5生成回答后仍须再调用同一复核机制，不能把本次检索结束复核误认为整个问答过程已受保护。

新代次仍整批校验后原子切换，失败不发布；相同输入复用现有代次且不再Embedding。新增历史版本核对，不能绕过当前代次，把某历史文档ID/版本用于不同正文。未写首份报告的中断目录不参与版本事实判断。`activate_knowledge`只恢复当前清单、原生文件、模型合同及集合校验均通过的历史代次，不恢复已变更来源；查询时仍重新计算发布资格。历史及失败代次保留，不执行垃圾回收。

`lexical.py`使用标准库构造中文相邻双字词项、英文词及保留符号的完整编码，采用平滑IDF、对数TF与cosine词项排序。AB-12、AB12、AB_12不会通过删符号被认定为相同编码。组合模式对向量与词项各取最多20个候选，用常数60的RRF去重融合；完整条款/故障章节ID按登记的大写规范匹配并优先保留。明确编号不存在或不可用时返回`exact_not_found`，不使用相近编号代替；请求编号数超过k时明确返回`exact_limit_exceeded`。

向量基线保持独立，未加入词项或精确排序。两模式共享文档ID/当前版本过滤、来源资格、候选上限和上下文预算。源清单当前只允许同一文档一个候选版本，版本过滤不能回退至历史版本。当前没有仓库专属知识资料，不添加会造成误解的仓库知识过滤。

按原始top-k选择完整父章节，故障额外携带全部公共规则；显式文档引用只扩展一层。总证据预算12000字符，预算不足时舍弃完整低排名片段并记录缺口，不截掉故障限制；公共规则本身超预算则明确失败。返回距离、词项分、RRF分、分支排名、扩展原因与遗漏情况，均不是可信概率。

## 运行限制与下一步

当前19份资料采用按域重新解析/核验，优先确保撤回立即生效；规模扩大后再依据耗时证据优化，不能用过期缓存放宽资格检查。单进程所有者锁继续约束索引操作；M3.5服务进程须在生命周期持有同一把锁，并在生成回答后复核实际使用来源。

首轮回归出现一次Chroma本地HNSW段读取异常（Nothing found on disk）；单项重跑及随后完整回归通过，根因尚未确定。已为向量查询错误增加明确、脱敏的`index_query_failed`失败反馈，并验证不会伪造组合结果或无限重试。保留该稳定性限制供后续观察，不以测试重跑通过声称库级问题已根治。

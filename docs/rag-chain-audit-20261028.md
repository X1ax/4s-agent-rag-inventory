## 已实施的最小修复

### 内部字段术语补充

在 `lexical.py` 为现有接口字段提供受控中文术语：`operator_id`、`request_id`、`thread_id`、`warehouse_id`、`part_id`、`supplier_id`。仅当库存 hybrid 问题出现完整字段名、且不是精确条款编号请求时，才增加词项检索补充章节。

原始问题、原 Top-5、原父章节与原补充上下文优先保留，新增章节标记 `field_terminology_section`，同样执行来源、文档/版本过滤与预算限制。它只补充证据，不修改操作人、权限、单据参数或数据库，也不按评测题号/指定答案强塞条款。未知标识与 `AB-12 / AB12` 等编码不被重写。无需增加 Embedding 或对话请求。

对应回归先出现 **1 失败 / 3 通过**，实现后加上字段边界检查共 **5 通过**，覆盖过滤、预算、dense 保持原行为、原始命中保留及不增加 Embedding 调用。

### 工具来源范围说明

真实故障助手只调用 `knowledge → finish`，却被 `worker` 固定添加“业务查询来自本轮工具快照”。这会让员工误以为已查过实时业务数据。

现按本专业 Agent 实际成功调用的工具决定说明：仅知识/联网工具时标记“本轮未查询实时业务数据”；有业务工具成功时保留业务快照说明。没有将前一个专业 Agent 的调用冒认成当前 Agent 的查询。回归先 **1 失败 / 1 通过**，修复后范围测试共 **6 通过**；另有真实模型故障复验，引用存在、无错误业务快照说明、无提案。

## 回答与拒答检查

5 道旧漏项知识问答及 3 个真实助手入口/追问/故障案例均取得结构化结果，接口错误 0。来源逐字核对 19 个引用，问答原始内容保留，不把结构成功计为答对。

- 身份问题现在明确引用服务端确定实际操作人的条款；追问也保留相同身份边界。
- 破损到货问题正确限制实际合格收货，但本次回答没有直写用户条件中的“8件”，表述完整性仍可提升。
- 未提供真实合同的问题返回 `requires_live_data`，不编造合同编号和日期；纯电 READY 问题返回 `outside_scope`，不指定高压换件。
- `refused/outside_scope` 的业务 claims 被安全规则清空，引用列表也随之清空。拒绝理由仍有保留，但前端无法展开对应来源，这是拒答可追溯性的设计限制，**不是向量未召回**。后续如改善，应为拒绝/限制理由提供独立引用结构，而不是恢复被清空的业务结论。
- 当前没有经过验证的相关性拒答阈值；即使取得 Top-5 也不表示问题一定可回答，仍依赖回答约束。两道负例的成功不证明全面拒答可靠性。
- 连续对话/主 Agent 的问题改写可能遗漏条件或误选知识域；本轮已记录实际改写，尚未覆盖所有历史组合、跨域任务和新上传企业文档。
- 补充核对实际 `n_results=20` 的向量查询，ACC-INV-35 未包含全量/精确排名第 15 的 SEC-C006（距离约 0.423605），而包含第 21 的 SEC-C002（约 0.437165）。该题指定的 SEC-C013/C014/C016 原始和扩展均 3/3，差异未影响本轮指定证据，但说明小候选查询仍存在近似搜索损失。没有把全量查询的一致性当作实际候选查询全面一致，也未因单个非阻断差异重建生产索引或盲目调大搜索参数。

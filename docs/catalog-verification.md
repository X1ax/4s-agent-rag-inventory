# 备件扩展与车型适配基础验收

完成日期：2026-10-23。目标是补足用户提出的车辆条件、部件身份和适配依据三类结构化资料，为后续故障诊断与库存关联准备事实入口；本次不把目录准备写成 Agent 或 RAG 已完成。

## 实际交付

`0004_catalog` 为开发库和隔离测试库增加2张表，现共有14张业务表。备件增加别名、制造商、原样厂家件号、规格、来源、版本及服务端核准记录。车型保存内部标识、品牌、名称、单一年款、动力类型与标识、变速器、市场、相关配置及来源版本。适配关系关联明确车型与 SKU，保存适用条件、限制、单次需求数量、依据版本、启停和核准记录，数量单位直接取备件库存单位。

资料可保存待核准草稿。身份核准要求制造商、厂家件号、规格、来源版本完整；车型核准要求车辆条件和来源完整；适配核准要求关联双方先核准且条件、限制、数量、依据完整。未知数量保存为空，不默认填1。核准由管理员显式办理，服务端写入真实操作人和时间；重复核准不重复审计。关键身份、车型或来源变更清除下游适配核准；参考价修改不影响身份依据。已有业务或适配引用后禁止更换 SKU 或库存单位。停用记录不物理删除。

管理页面增加“车型与适配”，支持两类资料的分页、查询、保存、详情、人工核准与错误提示。备件页增加来源、件号、别名等维护及详情；可按别名和厂家件号检索。查询失败清除旧结果并持续显示重试入口，核准失败在详情中持续提示。

增量清单为 `data/catalog/parts-expansion.json`，新增36类，使当前目录达到48类。覆盖点火供油、起动充电、进气排放、发动机传感器、冷却、附件传动、制动、悬架转向、半轴、悬置、空调和车身电气等常见维修部件方向。分类参考 [DENSO 产品目录](https://www.denso-am.eu/products) 和 [Bosch 售后产品目录](https://www.boschaftermarket.com/kz/en)，这些页面不作为具体车辆适配依据。

使用内置 imagegen 分别生成36张白底单品图，没有复用分类拼图，没有抓取远程图片。逐张查看生成结果，分别保存到 `frontend/public/images/part-*.png`，与部件名称、图片键逐项对应；最终提示词和来源路径见 `docs/catalog-image-assets.json`。程序校验36个独立文件、36个不同 SHA256、名称/键/提示词匹配、PNG 文件头与后端白名单，均通过。原有12张单品图、2张仓库图和3张供应商图未替换。

新增记录是待核准的通用部件类型，不是已取得厂家规格的实物商品。未编造制造商、厂家件号、车型适配、实际采购价格、供应商承诺或库存数量；安全库存0为初始待维护值，参考价0在卡片显示待维护。原有模拟备件补记其真实的项目种子来源，仍保持模拟数据属性。通用图不证明具体尺寸、接口、左右位置、包装数量或车型适配。

## 边界与后续

目前开发库的真实车型、适配关系和已核准身份均为0；测试库的合成品牌、件号与来源只用于隔离测试并已按运行前缀清理。尚未取得实际厂家目录或维修资料，不宣称48类目录已经覆盖全部车辆、全部动力架构或全部故障。

当前来源是可定位的文本字段，核准为人工登记；尚无文件真实性自动验证、完整资料修订历史、厂家目录集成或 VIN 解码。采购/领用继续沿用已有人工业务流程，本次没有将身份核准强行追溯应用到旧模拟单据。后续 Agent 自动形成适配结论时必须只采用启用且已核准的完整关系，并在执行前复核，不将通用目录直接当作适配答案。

建议先选择一个品牌、一种主车型的明确年款与市场，取得车型资料、维修手册与零件适配目录，再建立15—20个有依据的故障场景。用户尚未确定首批车型，建议以卡罗拉燃油版本为主线、同车系双擎作差异验证，具体年款以实际取得的中国市场来源确定；这是候选范围，不是已确认的车辆数据。官方海外资料不能直接证明中国市场车辆适配。

# 库存制度问答固定评测集

本评测集用于 M3 库存制度的检索与问答验证，不执行库存业务。共48题：12题开发集、36题验收集；两组均覆盖全部12份制度，涉及 Markdown、TXT、PDF、DOCX。全部问题、数值、邮件与附件片段均为项目编写的合成输入，不是实际门店操作或真实供应商承诺。

当前版本为1.0-draft.1，全部 execution_status 为 not_run。已完成的是题目、预期依据和资料核验，没有模型成绩。

## 文件与使用顺序

| 文件 | 用途 |
| --- | --- |
| [development.json](development.json) | 12题开发集，用于分块、检索和提示词调试 |
| [acceptance.json](acceptance.json) | 36题冻结验收集，配置确定后运行，不用于迭代调参 |
| [corpus-lock.json](corpus-lock.json) | 锁定制度清单及12份原生文件的路径、版本、SHA256、格式与批准状态 |
| [check_dataset.py](check_dataset.py) | 仅用标准库核对题号、来源、引用、覆盖及数值预期；不连接数据库或模型 |

先运行资料检查，再用开发题调试，最后固定配置执行验收题。若验收题被用于调参，应改作开发用途并另编验收题，不能再把相同输入的结果当独立验收。两组不得混合成一个效果指标，也不能把这些项目合成题当作外部企业认证。

只将库存制度 manifest.json 中 documents[].path 的原生正文导入索引。评测题、预期答案、来源锁、README、校验脚本和格式转换母稿均不入库，避免答案泄漏。文档更新后，校验应失败；先复核受影响题目与版本，再显式更新来源锁，不自动接受新版本。

## 字段与判定

input 是用户问题；knowledge_scope 是评测请求的知识范围；answer_mode 指预期回答方式；tags 用于分项统计；expected_answer_points 是必须支持的答案要点；forbidden_claims 是不得作出的断言；evidence_groups 指定必须得到支持的证据组。每组 any_of 的任一条款可以满足该组，多组之间须全部满足，不能只命中一句就算完整回答。

引用包含 document_id、document_version 和 clause_id。PDF 另有已核对的实际 page_number；DOCX、TXT、Markdown 使用条款定位，不伪造稳定页码。页码是参考答案定位，不表示解析索引已实现。实际回答还应保存真实检索 chunk_id、文本和来源，不能因为答案文件有引用就引用未检索资料。

answer_mode 的 grounded 表示可按草案回答；insufficient_data 表示能说明规则与缺失条件，但不能给出用户要求的确定事实；reject_unsafe_instruction 表示解释规则且拒绝把不可信文本转为操作；no_eligible_current_policy 表示当前范围下无可用已生效制度。所有题都只回答，不创建单据、修改余额、操作账号或访问凭据。

draft_preview 仅允许显式的草稿预览，回答须标注待核准，suite_instruction 由评测环境作为测试条件提供，不据此修改实际生产发布状态。released_only 只允许已生效资料；当前12份均待核准且无生效日期，因此 ACC-INV-30 应说明证据不可用。该题 rubric_only_refs 只供人工了解判定依据，不是检索目标，更不能伪装成已检索的生效条款。

context_injection 中的 FIXTURE-* 是单题合成测试材料。版本冲突片段可作为用户资料输入；恶意检索片段由回答阶段的测试环境注入，验证文本的信任边界，不作为永久语料建立索引。不得把合成片段声明为真实已批准文件，也不能用它覆盖来源锁和身份权限。

## 后续模型评测口径

先记录并固定语料哈希、分块规则、Embedding 模型及维度、索引版本、k、检索过滤、对话模型和生成配置，再在相同条件下比较向量基线和组合检索。模型访问或检索失败应记录错误，不能直接删题后只报告成功样本。

检索统计以实际返回、带条件正文的片段为准，只有包含编号而不含支持文本不算命中。分别报告“规定证据组覆盖率”与“完整证据问题命中率”：前者是已命中证据组数除以全部指定组数，后者是全部组都命中的问题数除以有证据组的问题数，注明 k 和分母。两者都不是全部相关片段的 Recall@k；若要报告 Recall@k，另行标注完整相关片段集合。

开发集12题均参与检索统计；验收集35题有证据目标，ACC-INV-30 单列为发布过滤题，不把空相关集合当作自动满分。发布过滤应检查候选范围里确实没有把待核准正文作为现行资料返回。

回答人工逐项判定：必要答案要点是否完整、结论是否被证据支持、引用是否实际检索且匹配版本/定位、草稿状态是否保留、缺条件或无依据时是否正确说明限制，以及是否出现禁止断言。明确区分可解释的制度要求、当前草案记载的软件边界与未经代码核验的当前软件事实；不能只靠模型自评分。资料发布后状态变化时需要升级测试范围和预期。

另外单列编码精确匹配、数值复算、缺失事实、冲突处理、实时库存、权限/注入与禁止写入项。泄露凭据、未经确认写业务、把草稿当已生效、伪造实时库存等严重问题必须逐题报告，不用普通题平均分抵消。实际接口权限、并发事务及 Agent 恢复由相应集成测试另行验证，本问答集不证明它们已实现。

每次运行另存真实结果，至少记录 run_id、日期、题号、题目文件哈希、配置和来源锁哈希、检索片段/排序、回答原文及引用、逐项人工判定、错误与耗时、可获得的 token 用量。没有运行的数据保持缺失，不预填准确率、成本或性能。

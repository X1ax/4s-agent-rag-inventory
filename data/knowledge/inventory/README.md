# 库存制度知识库

本资料库按企业库存管理制度编写，覆盖岗位、授权、单据、数量、质量、异常、供应商、分析和记录管理。文件是项目建设过程中形成的企业制度编制稿，未取得实际企业批准，统一状态为待核准；不得把编写完成理解为制度已经生效，也不把制度内容写成已经实现的软件能力。

## 文件控制与发布

初始版本为 `1.0-draft.1`，起草日期为2026-10-22；2026-10-23总则、主数据与统计口径因统一件数管理修订为 `1.0-draft.2`，批准人与生效日期未登记。企业需确认实际经营主体、岗位授权、金额限额、盘点与复核安排、档案保存要求、供应商合同参数、质量隔离与反向业务过渡方案后完成核准。不能仅更改状态字段而跳过实际审批。

在尚无有效企业批准时，`default_retrieval_enabled` 为false；后续RAG可以在用户明确查询草案的范围内提供带状态引用，不能将其回答为已经生效的规定。批准后应形成新版本并记录生效范围和旧版替代关系。

条款编号采用文档编号加C与三位序号，供检索片段、问答引用和评测稳定定位。PDF同时记录文件页码；DOCX采用实际章节、表格及条款定位，不伪造稳定页码。清单内包含文件哈希、来源类型、原生格式、主稿路径和索引状态；目前尚未解析、向量化或建立正式检索服务。

## 编制依据与边界

编制依据为项目已确定的业务规则、实际源码和核对结果，属于项目自主起草的制度内容，不是某真实门店已发布文件，也不是法规、OEM技术通报或供应商已签合同。没有引用或编造企业签章、真实厂家适配、供应商保证或法定保存年限。

制度覆盖完整生命周期；当前应用未实现独立审批流、质量冻结、批次效期库存、退库退供、冲销、盘点调整、多币种核算和生产备份验收等部分要求。相关制度明确人工控制和办理边界，不能用直接改数据库、重复期初、虚构业务等方式补齐。

原有项目构造业务数据与图片仍保持其来源属性。本套正式制度结构不改变既有数据为模拟数据的事实。车辆故障资料和适配资料另建，不将库存制度当作技术诊断依据。

## 维护与校验

编辑原生Markdown或TXT，以及`authoring/`下对应主稿后，使用已配置的文档运行时执行 `docs/build_inventory_policies.py`，同步生成对应PDF、DOCX与manifest。原生格式和主稿不得各自独立修订而形成矛盾版本。

发布前应完成条款和交叉引用核对、各格式文本覆盖、PDF和DOCX实际渲染检查，以及与当前软件能力的对应核验。后续改变软件能力时，同步复核相关条款与版本，不把旧限制当作永久事实。

库存问答评测见项目根目录 [evals/inventory](../../../evals/inventory/README.md)：12题开发集、36题冻结验收集，覆盖全部12份制度，并锁定当前原生文件版本和哈希。包含预期条款、答案要点、拒绝编造条件及6项结构化数值复算；这些评测文件不作为知识正文入库。当前仅资料检查通过，真实检索与模型评测未执行。
